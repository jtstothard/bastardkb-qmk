<task type="manual">
  <name>Task 1: Test DPI preset cycling via keyboard</name>
  <action>
Test DPI preset cycling using hardware controls:

**Test Procedure:**
1. Flash firmware with VIA support to Dilemma v3 hardware
2. Press DPI_MOD (POINTER_DEFAULT_DPI_FORWARD) key to cycle forward through presets
3. Press DPI_RMOD (POINTER_DEFAULT_DPI_REVERSE) key to cycle backward through presets
4. Observe pointer movement speed changes at each preset

**Expected Results:**
- 7 DPI presets available (0-6): 200, 400, 600, 800, 1000, 1200, custom
- Forward cycling: 200 → 400 → 600 → 800 → 1000 → 1200 → custom → 200 (wrap)
- Backward cycling: 200 → custom → 1200 → 1000 → 800 → 600 → 400 → 200 (wrap)
- Pointer speed increases proportionally with DPI value
- Each preset press produces immediate, noticeable speed change

**Validation:**
- [ ] Forward cycling works through all 7 presets
- [ ] Backward cycling works through all 7 presets
- [ ] Wraparound occurs correctly (custom → 200 and 200 → custom)
- [ ] Pointer speed matches DPI preset (200 = slowest, 1200 = fastest)
- [ ] No firmware crashes or freezes during cycling

**Record Results:**
- Document actual DPI values observed
- Note any unexpected behavior or skipped presets
- Measure approximate pointer speed (inches/second if possible)

<task type="manual">
  <name>Task 2: Test custom DPI value input and preset switching</name>
  <action>
Test custom DPI configuration and preset → custom switching:

**Test Procedure:**
1. Open VIA configurator (https://usevia.app)
2. Connect Dilemma v3 and load via.json menus
3. Navigate to "Pointer" → "Custom DPI"
4. Set custom DPI to various values: 200, 800, 1600, 2400, 4000
5. After each value, click "Save" button
6. Switch to custom preset (preset 6) using DPI_MOD key
7. Observe pointer speed matches custom DPI value

**Expected Results:**
- VIA accepts custom DPI values in range 200-4000
- Values < 200 are rejected or clamped to 200
- Values > 4000 are rejected or clamped to 4000
- Save button persists custom DPI to EEPROM
- Switching to preset 6 (custom) applies saved value
- Pointer speed matches custom DPI (800 = 2× speed of 400, etc.)

**Validation:**
- [ ] VIA accepts all valid custom DPI values (200-4000)
- [ ] VIA rejects invalid values (< 200 or > 4000) OR clamps to range
- [ ] Save button writes to EEPROM (value persists after power cycle)
- [ ] Preset 6 applies custom DPI value correctly
- [ ] Pointer speed scales proportionally with custom DPI
- [ ] No firmware crashes with extreme values (200, 4000)

**Test Cases:**
- Valid: 200, 400, 800, 1200, 1600, 2000, 2400, 2800, 3200, 3600, 4000
- Boundary: 199 (reject/clamp to 200), 200 (accept), 4000 (accept), 4001 (reject/clamp to 4000)
- Extreme: 200 (minimum), 4000 (maximum)

**Record Results:**
- Document which values were accepted/rejected
- Note any clamping behavior
- Verify EEPROM persistence by power cycling after setting custom DPI
  </action>
  <verify>Test log shows custom DPI validation results with boundary case behavior</verify>
  <done>Custom DPI value input tested with boundary cases (200-4000 range validated)</done>

<task type="manual">
  <name>Task 3: Test sniping DPI mode</name>
  <action>
Test sniping DPI functionality and keyboard/VIA controls:

**Test Procedure Part A - Keyboard Controls:**
1. Press SNIPING (SNIPING_MODE) key to toggle sniping mode
2. Observe pointer speed decrease dramatically
3. Press S_D_MOD (POINTER_SNIPING_DPI_FORWARD) to cycle sniping DPI forward
4. Press S_D_RMOD (POINTER_SNIPING_DPI_REVERSE) to cycle sniping DPI backward
5. Press SNP_TOG (SNIPING_MODE_TOGGLE) to toggle sniping mode
6. Verify pointer speed returns to normal when sniping disabled

**Test Procedure Part B - VIA Configuration:**
1. Open VIA configurator → "Pointer" → "Sniping DPI"
2. Test sniping DPI preset slider (presets 0-3)
3. Set to each preset and click "Save"
4. Toggle sniping mode and observe pointer speed at each preset

**Expected Results:**
- 4 sniping DPI presets: 200, 400, 600, 800
- Sniping mode reduces pointer speed significantly (for precision work)
- Sniping toggle (SNIPING or SNP_TOG) enables/disables mode
- Forward cycling: 200 → 400 → 600 → 800 → 200 (wrap)
- Backward cycling: 200 → 800 → 600 → 400 → 200 (wrap)
- VIA slider updates sniping presets (0 = 200, 1 = 400, 2 = 600, 3 = 800)
- Save button persists sniping DPI to EEPROM

**Validation:**
- [ ] Sniping mode toggle works (SNIPING and SNP_TOG keys)
- [ ] Pointer speed decreases significantly when sniping enabled
- [ ] Sniping DPI cycling works (S_D_MOD forward, S_D_RMOD backward)
- [ ] 4 sniping presets available (200, 400, 600, 800)
- [ ] VIA sniping DPI slider controls presets correctly
- [ ] Save button persists sniping DPI to EEPROM
- [ ] Power cycle preserves sniping DPI setting
- [ ] No firmware crashes when toggling sniping mode rapidly

**Record Results:**
- Document sniping DPI values at each preset (0-3)
- Note pointer speed difference (sniping vs normal)
- Verify EEPROM persistence by power cycling
  </action>
