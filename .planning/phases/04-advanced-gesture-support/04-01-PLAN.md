**Requirements for 3 vs 4 Finger Swipe Distinction:**

1. **Firmware Changes (digitizer_mouse_fallback.c):**
   - Track exact finger count (not just >= 3)
   - Store finger_count at swipe state entry
   - Branch on finger_count in swipe keycode logic:
     - 3 fingers → three_finger_swipe_keycode
     - 4 fingers → four_finger_swipe_keycode

2. **EEPROM Usage:**
   - Byte 18-19: Currently swipe_keycode (single mapping)
   - Need: Two separate 16-bit keycode fields:
     - three_finger_swipe_keycode (Bytes 18-19)
     - four_finger_swipe_keycode (Bytes 20-21, but need to adjust layout)

3. **Implementation Approach:**
   - Extend State enum or add finger_count tracking variable
   - Update Swipe state case to check finger_count before tap_code()
   - Add conditional logic based on VIA config enables

4. **Backward Compatibility:**
   - Default 3-finger swipes to existing keycodes (QK_MOUSE_BUTTON_3/4, KC_LEFT_GUI, KC_ESC)
   - Default 4-finger swipes to macOS equivalents (Tab+Cmd for app switcher, Ctrl+Left/Right for spaces)
   - Check VIA enables before executing swipe keycodes

**Pinch-to-Zoom Gesture Detection Algorithm:**

1. **Gesture Pattern:**
   - Two fingers start at distance D1
   - Fingers move to new distance D2
   - D2 > D1 + threshold = Zoom In (spread)
   - D2 < D1 - threshold = Zoom Out (pinch)

2. **Implementation Requirements:**
   - Track two finger positions: finger[0].x, finger[0].y and finger[1].x, finger[1].y
   - Calculate distance: sqrt((x2-x1)² + (y2-y1)²)
   - Store initial_distance on gesture start (contacts == 2)
   - Monitor distance changes while contacts == 2
   - Trigger zoom gesture when distance change > threshold

3. **State Machine Extension:**
   - Add Zoom state to enum: None, Down, MoveScroll, Tapped, DoubleTapped, Drag, Swipe, Zoom, Finished
   - Enter Zoom state when contacts == 2 and fingers move apart/together
   - Detect zoom_in vs zoom_out based on distance delta
   - Tap zoom keycodes based on direction

4. **Keycode Mappings:**
   - Zoom In: KC_EQUAL (plus/equals key, common zoom in)
   - Zoom Out: KC_MINUS (minus key, common zoom out)
   - Configurable via VIA (Bytes 22-25: zoom_in_keycode, zoom_out_keycode)

5. **Integration Points:**
   - Check pinch_to_zoom_enabled from VIA config
   - Call tap_code() for zoom keycodes
   - Filter via g_gesture_state.zoom (already exists from Phase 3)

6. **Complexity Assessment:**
   - Medium complexity - requires floating-point or fixed-point math for distance calculation
   - QMK may not have sqrt() - consider squared distance comparison instead
   - Threshold tuning required for usability
